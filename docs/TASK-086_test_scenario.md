# TASK-086 관리자 상품 추천 예외 결정 검증 시나리오

## 적용 대상

- `docs/TASK-086_product_suggestion_admin_decision.sql`
- `js/product-suggestion.js`
- `admin/product-suggestion-votes.html`

| ID | 조건 | 확인 항목 | 기대 결과 |
|---|---|---|---|
| TS-01 | 관리자(100+)가 투표중 추천의 상세 모달을 연다 | 결정 제어 노출 | `채택 결정`, `불채택 결정` 버튼이 상세 모달에서만 표시된다. |
| TS-02 | 관리자(100+)가 투표 완료 전 `채택 결정`을 실행한다 | 채택 처리 | `products`에 달란트 0, 순번 0, 학생 대상, 비활성 상품이 생성되고 추천 상태가 `adopted`가 된다. |
| TS-03 | 관리자(100+)가 투표 완료 전 `불채택 결정`을 실행한다 | 불채택 처리 | 추천 상태가 `rejected`가 되며 상품은 생성되지 않는다. |
| TS-04 | 부서 담당 교사(60-99)가 같은 상세 모달을 연다 | 권한 분리 | 일반 찬성/반대 투표만 가능하고 관리자 결정 버튼은 표시되지 않는다. |
| TS-05 | 완료된 추천을 다시 결정한다 | 중복 처리 방지 | RPC는 기존 처리 상태만 반환하고 새 상품이나 중복 이력을 만들지 않는다. |
| TS-06 | 관리자 결정 후 로그를 확인한다 | 비밀 투표 보호 | 채택/불채택 결과와 `관리자 예외 결정` 처리유형만 기록하고 투표자·개별 찬반·익명 집계는 기록하지 않는다. |

## 수동 확인 절차

1. `TASK-085_product_suggestions.sql` 적용 후 `TASK-086_product_suggestion_admin_decision.sql`을 실행한다.
2. 60+ 투표자가 포함된 투표중 추천을 준비하고, 100+ 관리자 계정으로 `상품 > 상품 추천 투표` 상세를 연다.
3. 채택 또는 불채택 결정을 실행한 뒤 추천 상태, 상품 관리 목록, 작업 이력을 확인한다.
4. 60-99 계정으로 다시 로그인하여 관리자 결정 제어가 보이지 않는지 확인한다.
