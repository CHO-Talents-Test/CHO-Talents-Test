🔔 Slack 알림 룰

브라우저에서 발생한 운영 이벤트와 외부 서비스 무료 할당량 경고가 Supabase Edge Function을 거쳐 Slack 채널로 전송되는 기준입니다. v4.2.9 기준 WARN+ 로그 알림은 영어로 저장된 action/details를 한글로 치환해 전송하며, 서비스 사용량은 매시간 정각에 수집하고 수집 이력은 180일 보존합니다.

1. 전체 호출 구조

화면 이벤트 → sendSlackNotify(type, data) → _sb.functions.invoke('slack-notify') → Edge Function → Slack Incoming Webhook
구간담당 파일역할
브라우저 공통 유틸js/slack-notify.jssendSlackNotify(type, data)를 제공하고 동일 알림을 5초 동안 중복 전송하지 않습니다.
로그 알림js/activity-log.jsWARN, ERROR, FATAL, CRITICAL 로그 기록 시 log_alert를 Edge Function으로 보냅니다. 액션명과 details는 로그 화면과 같은 한글 매핑으로 치환한 뒤 전송합니다.
Edge Functionsupabase/functions/_shared/slack-notify.ts알림 유형과 부서명에 따라 사용할 Slack Webhook Secret을 선택하고 Block Kit 메시지를 구성하며 성공/실패 사용량을 기록합니다.
Slack 호출은 fire-and-forget 방식입니다. 실패해도 구매, 가입, Q&A 같은 사용자 작업은 중단하지 않지만, 실패 유형·응답 상태·사유를 활동 로그에 남겨 원인을 확인할 수 있습니다.

로그 알림의 액션 라벨과 상세는 js/activity-log.js의 코드북/공통 details 매핑을 따릅니다. 저장은 영어 key 기준이지만 Slack에는 한글 작업명과 한글 상세만 표시합니다.
상품 관리에서 썸네일 이미지(image_url)와 상세 설명 이미지(detail_image_url)를 저장해도 정상 성공 건은 Slack 대상이 아닙니다. 업로드/저장 실패처럼 WARN 이상 로그가 남는 경우에만 log_alert로 운영 채널에 전송됩니다.
위치 제한 QR에서 위치 권한 차단이 발생하면 QR_LOCATION_PERMISSION_BLOCKED가 INFO 로그로 저장됩니다. INFO 로그는 기본 Slack WARN+ 알림 대상이 아니며, 현장 문의 분석은 로그 화면에서 action 필터로 확인합니다.
v4.2.8의 달란트 지급 대상일·QR 발생 시각 분리는 Slack 알림 유형을 추가하지 않습니다. 지급 성공/중복 거부에서 WARN 이상 로그가 발생한 경우에만 기존 log_alert 규칙으로 운영 채널에 전송하며, 지급 대상일 확인은 달란트·QR 관리 화면과 로그 상세에서 합니다.
서비스 할당량 알림은 매시간 정각 수집 결과를 기준으로 하며, 지표의 초기화 주기별로 각 임계값을 한 번만 발송합니다. 월/일 초기화가 시작되면 새 주기의 70%·85%·95% 알림을 다시 받을 수 있습니다.
180일 초과 수동 정리 성공 로그는 INFO라 기본 Slack 알림 대상이 아닙니다. RPC 권한/적용 오류처럼 ERROR로 남는 실패 로그는 log_alert 기준에 따라 운영 채널 알림 대상입니다.
v3.79.0의 성공 로그인 이력 저장과 관리 > 사용자 통계 조회는 Slack 알림 이벤트가 아닙니다. 로그인 이력 기록 실패는 사용자 로그인 흐름을 중단하지 않고 콘솔 경고로만 확인합니다.
서비스 통계의 최근 수집 실패 항목은 수집 실행 이력의 서비스·수집 항목·오류 메시지를 화면에서 확인하는 운영 진단 정보입니다. 이 목록 자체는 Slack 알림을 새로 보내지 않으며, 수집 실패가 WARN+ 활동 로그로 기록된 경우에만 기존 log_alert 규칙이 적용됩니다.
상품 추천 등록 완료와 채택/불채택 종료는 운영관리 Slack 알림 이벤트입니다. 등록 알림에는 상품명·등록 시각, 종료 알림에는 상품명·결과·찬성/반대/총 득표 수·종료 방식만 포함합니다. 비밀 투표를 위해 추천자·개별 투표자 정보는 Slack으로 보내지 않습니다. 진행 중 집계와 직접 결정·정원 감소 종료는 profiles.is_super_admin=true인 최고관리자만 실행할 수 있습니다.
상품 일괄 등록과 일반 관리 변경 로그도 정상 성공 시 Slack 알림 대상이 아닙니다. 실패가 WARN 이상으로 기록될 때만 변경 항목·사유를 포함한 일반 log_alert 규칙이 적용됩니다.

Secret용도
SLACK_WEBHOOK_PART1 ~ SLACK_WEBHOOK_PART51부~5부 부서별 채널
SLACK_WEBHOOK_WORSHIP예배부 채널

SLACK_WEBHOOK_OPERATIONS운영 로그 채널

Webhook URL 원문은 정적 HTML, JS, app_config에 저장하지 않습니다. Supabase Edge Function Secret 또는 서버 환경변수에만 저장합니다.
SLACK_WEBHOOK_OPERATIONS는 WARN+ 로그, 서비스 할당량 70%·85%·95% 알림, 상품 추천 등록/투표 종료 알림이 함께 사용하는 운영관리 채널입니다.

4. 신규 알림 추가 기준

  1. 이벤트가 발생하는 화면에서 sendSlackNotify('새_type', data)를 호출합니다.
  2. supabase/functions/_shared/slack-notify.ts의 라우팅 함수와 메시지 생성 로직에 새 type을 추가합니다.
  3. 필요한 Webhook Secret을 Supabase Edge Function 환경변수에 추가합니다.
  4. 운영 문서와 이 페이지에 라우팅 기준, 포함 정보, 실패 시 동작을 기록합니다.
