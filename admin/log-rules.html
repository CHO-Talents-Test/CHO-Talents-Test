📋 로그 작성 룰

시스템 로그가 기록되는 기준과 규칙을 설명합니다. 수정·상태 변경 로그는 대상, 변경 항목, 이전 값, 변경 값을 구조화해 저장하며 비밀번호·비밀 투표 정보는 기록하지 않습니다. 로그 화면과 Slack 알림은 저장된 영어 action/details를 한글로 치환해 보여줍니다.

📊 로그 레벨 체계

7단계 로그 레벨을 사용하며, ERROR 이상은 확인(Acknowledge) 처리가 필요합니다.

레벨용도확인 필요사용 기준
TRACE 개발/디버깅 추적 ❌ 개발 환경에서만 사용 (현재 미사용)
DEBUG 디버깅 정보 ❌ 개발 환경에서만 사용 (현재 미사용)
INFO 정상 동작 기록 ❌ 모든 성공 작업, 정상 이벤트 (PAGE_VIEW는 저장하지 않음)
WARN 경고/거부 ❌ 권한 거부, 비즈니스 규칙 차단, 비정상 시도
ERROR 오류 발생 ✅ DB/RPC 실패, JavaScript 예외, API 오류
FATAL 치명적 오류 ✅ 서버 연결 불가 등 시스템 장애
CRITICAL 긴급 오류 ✅ 예약됨 (현재 미사용)

🏷️ 액션 네이밍 규칙

패턴레벨의미예시
ACTION_NAME INFO 성공한 작업 USER_CREATE, TALENT_GIVE, ORDER_REQUEST_SUCCESS
*_DENIED WARN 권한/규칙에 의한 거부 USER_CREATE_DENIED, TALENT_GIVE_DENIED
*_FAIL ERROR DB/RPC 오류 반환 PASSWORD_CHANGE_FAIL, PURCHASE_LOAD_FAIL
*_ERROR ERROR JavaScript 예외 발생 LOGIN_ERROR, PASSWORD_CHANGE_ERROR

🤖 자동 로깅 항목

코드 호출 없이 자동으로 기록되는 항목들입니다.

액션레벨트리거기록 데이터
PAGE_VIEW INFO 모든 페이지 로드 시 autoLogPageView() v3.40.0부터 저장하지 않음
JS_ERROR ERROR window.onerror (캐치되지 않은 JS 에러) 에러 메시지, 파일명, 라인/컬럼
PROMISE_REJECTION ERROR unhandledrejection 이벤트 rejection reason
CONNECTION_FAIL FATAL 메인 페이지 Supabase 연결 실패 에러 메시지
PAGE_VIEW: v3.40.0부터 페이지 조회 로그(PAGE_VIEW) 기록이 비활성화되었습니다. autoLogPageView() 호출은 유지되지만 activity_logs에 저장되지 않습니다.
Slack 알림: WARN, ERROR, FATAL, CRITICAL 로그는 js/activity-log.js에서 log_alert로 Edge Function slack-notify를 호출합니다. 자세한 라우팅은 운영 > Slack 알림 룰에서 확인합니다.

⚙️ writeLog 함수 구조

writeLog(level, action, page, details)
// level: 'TRACE'|'DEBUG'|'INFO'|'WARN'|'ERROR'|'FATAL'|'CRITICAL'
// action: 작업 식별자 (예: 'USER_CREATE')
// page: 페이지 경로 (null이면 자동 감지)
// details: 처리 상세 정보 객체 (공통 필드는 저장 전 제거)

편의 함수

logInfo('TALENT_GIVE', { userId, amount, description })
logWarn('TALENT_GIVE_DENIED', { userId, reason: '권한 부족' })
logError('TALENT_GIVE_FAIL', { userId, error: err.message })
details 저장 기준: v3.74.0부터 writeLog()는 details를 영어 key로 정규화하고 중복 항목을 제거합니다. action, 작업자, 로그 작성 일시, 로그 레벨, 발생 페이지처럼 기본 컬럼 또는 화면 기본 영역에 표시되는 값은 details에 저장하지 않습니다.

기본 표시 필드와 details 제외 항목

구분처리 기준
작업activity_logs.action에 영어 action code로 저장하고 화면/Slack에서 한글 작업명으로 치환
사용자 계정profiles.display_name(username) 우선 표시. 승인 전 계정은 registration_requests.display_name(username) 기준으로 표시
일시/레벨/페이지created_at, level, page 기본 컬럼으로 표시하고 details에는 중복 저장하지 않음
처리 상세대상, 금액, 상태 변경, 오류 메시지, 사유 등 실제 처리 내용만 영어 key로 details에 저장
클라이언트 정보_client, 클라이언트, IP, 브라우저, OS, 화면 크기, 기기 정보는 신규 로그에 저장하지 않음

구분기록 기준
추천 등록PRODUCT_SUGGESTION_CREATE에 추천 상품 ID, 상품명, 등록 시점 정원/과반만 기록합니다.
개별 투표비밀 투표를 위해 개별 찬성/반대와 투표자 식별 정보는 activity_logs에 기록하지 않습니다.
최고관리자 종료/결과PRODUCT_SUGGESTION_CLOSE, PRODUCT_SUGGESTION_ADOPT, PRODUCT_SUGGESTION_REJECT에는 종료 또는 최고관리자 예외 결정 처리유형만 기록합니다. 진행 중 집계 열람, 직접 결정, 정원 감소 종료는 profiles.is_super_admin=true 계정만 가능하며, 종료 건의 익명 집계 외에 투표자 목록과 개별 찬반은 남기지 않습니다.
채택 자동 지급PRODUCT_SUGGESTION_ADOPTION_TALENT에는 추천 상품, 상품 추천 채택 항목, 1달란트 자동 지급 사실만 기록합니다. 추천 등록자·투표자 식별 정보와 개별 찬반은 기록하지 않습니다.
운영관리 Slack추천 등록 완료와 채택/불채택 종료 시 별도 Slack 이벤트를 전송합니다. 등록 알림은 상품명·시각, 종료 알림은 상품명·결과·익명 득표 수만 포함하며 추천자·투표자 식별 정보는 전송하지 않습니다.
추천자 이력은 채택 상품의 products.created_by와 추천 연결 테이블에서 관리하며, 투표 화면과 투표 로그에는 표시하지 않습니다.

📝 참고 사항

저장소: 모든 로그는 Supabase activity_logs 테이블에 저장됩니다.
DB 권한: 로그가 DB에 쌓이지 않으면 docs/TASK-047_activity_logs_grants.sql로 activity_logs INSERT 권한과 RLS 정책을 복구합니다.
소프트 삭제: 로그는 물리적으로 삭제되지 않고 is_deleted=true로 표시됩니다.
한글 라벨/상세: 신규 로그는 영어 action/details로 저장하고, 화면과 Slack 알림에서 js/codes.js 기본 코드북, DB activity_logs.action 코드 그룹, 공통 details key 매핑을 기준으로 한글 치환합니다. 기존 DB의 한글 별칭/중복/client details는 docs/TASK-074_activity_logs_english_details.sql로 정리합니다.
로그 관리 페이지: 운영 > 로그에서 조회/확인 처리/삭제 가능. 상단 미확인 ERROR+ 로그(확인 필수) 그리드는 행 전체를 클릭하면 해당 로그의 상세 모달을 열며, 상세·확인하기 버튼은 행 이동과 분리되어 동작합니다. 페이지당 항목 수 콤보 박스는 필터 영역 가장 아래의 삭제 대기 목록 줄 오른쪽에 배치되며, 선택값은 계정별 설정으로 저장됩니다. 확인 완료된 활동 로그는 180일 보존 후 자동 정리되며, 관리자(100+)는 180일 초과 실제 삭제 버튼으로 즉시 정리할 수 있습니다. 미확인 로그는 확인 완료 전까지 자동/수동 실제 삭제되지 않으며 선택 삭제 체크박스도 비활성화됩니다.
